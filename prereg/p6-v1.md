This document fixes the formal statements, the experiments, the hypotheses and the decision
rules before any paper 6 experiment code, model call or result exists. Once tagged, everything
in it is binding, and any departure is a deviation under §11. Terms: a *sensor* writes an
*observation*; the deterministic contract computes the verdict.

## 1. Setting

Inherited from paper 5: candidate attributes `A`, reachable tuples `R`, verdict function
`g: R → {allow, deny}`, and a sufficient contract `C ⊆ A` such that `g` is determined by `C` on
`R`.

New objects:

- A partition `C = F_r ∪ F_s`. Recorded fields `F_r` are read from systems of record with
  metadata. Sensed fields `F_s` are produced by sensors.
- A sensor `S_i` for field `i` maps an evidence document `d` to a score `s ∈ [0, 1]` for each
  candidate value of field `i` (§5.1).
- An admission policy `A_i` maps scores to `true`, `false` or `unknown` using thresholds
  `τ_i^true`, `τ_i^false` frozen on a validation split at false-positive ceiling `ε` (§5.2).
  `unknown` routes to deny.
- A **sensed record**: `(field, value, score, admission, sensor id and version, source document
  SHA-256, sensed_at)`. It carries metadata, so SARC-DQ predicates apply to it (freshness of
  sensing, sensor version pin, lineage to the document). The sensor never emits a verdict.
- **Contract evaluation from observations.** Given an observed value for every field of `C`
  (recorded values as recorded, sensed values as admitted), the verdict is `g(t')` for any
  `t' ∈ R` that agrees with the observations on `C`. Sufficiency makes this well defined. If any
  sensed field is `unknown`, or no reachable tuple agrees with the observations, the verdict
  is `deny`.
- **Exposure**: the event `g(recorded ∪ sensed) ≠ g(recorded ∪ true)`. A change from deny to
  allow is *unsafe*; a change from allow to deny is *fail-closed*.

Per field `i` and a distribution over items: `e_i` is the rate at which the admitted value is a
definite value different from the true value; `u_i` is the rate at which the field is
`unknown`; `e_i^+` is the rate at which the admitted value is wrong *and* evaluating the
contract with that value in place of the true value (all other fields true) turns a true deny
into allow.

## 2. Architecture registered (claim C1)

A sensed field enters the gate only as a sensed record (§1) with provenance, score and
admission stamp. The admission policy is a threshold with abstention per field, never a
weighted combination across fields. The gate of paper 1 and the compiler of paper 5 are
unchanged; this paper adds a record type and a cost model. Sensed records live in the governed
buffer and are never written to source systems.

## 3. Propositions (statements registered; proofs and checkers in Phase B)

- **S1 (union bound).** For a contract with sensed-field set `F_s`,
  `P(verdict change) ≤ Σ_{i∈F_s} (e_i + u_i)` and `P(deny→allow) ≤ Σ_{i∈F_s} e_i^+`.
  A verdict change requires at least one sensed field whose admitted value differs from the
  true value or is unknown; the allow-ward refinement uses the direction of `g` in each field,
  computed on `R`.
- **S2 (monotonicity and selection).** Removing a sensed field from `F_s`, keeping the contract
  sufficient, does not increase the bound. Among the reducts of paper 5, the sensing-aware
  objective `min |F_s|` (or `min Σ e_i` under a declared error model) is a valid cost model
  under paper 5's `observation_costs` interface. No new solver is needed.
- **S3 (fail-closed).** If `unknown` routes to deny and every admitted-wrong event in `F_s` is
  deny-ward, then `P(deny→allow) = 0`. Stated as a conditional; E1 and E2 report whether the
  condition held.
- **N6 (negative).** There is a two-field configuration with an allow-ward admitted-wrong
  event, in which S3's condition fails and the S1 deny-to-allow bound is attained. Zero unsafe
  changes is therefore a property of tested configurations, not of the mechanism.

Checkers (Phase B): exhaustive over small synthetic sensors with declared error rates;
property-based tests that the inequalities hold in every generated case; a witness generator
for N6. Each statement is tagged `machine-checked` only where a checker covers it,
`checked-scope-only` otherwise, and `pending-human-review` for the general proofs.

### 5.2 Admission policy

For each sensor, experiment, field and candidate value `v`, thresholds are set on the
validation split, pooled over the three noise levels, at false-positive ceiling `ε = 1%`
(E3 adds `ε = 5%`), by the jev-v2 §7 procedure: `τ_v^true` is the smallest candidate with at
most `ε` of records whose true value is not `v` scoring at least `τ_v^true`; `τ_v^false` is the
largest candidate with at most `ε` of records whose true value is `v` scoring at most
`τ_v^false`. Invalid answers are excluded from threshold setting.

Each value's score maps to `true`, `false` or `unknown` as in jev-v2 §7. The field's admitted
value is `v` if exactly one value maps to `true`; otherwise the field is `unknown`, which
denies. Thresholds are written to a committed file before any test-split call of that
experiment, as in jev-v2.

### 5.4 E1: the bound on a second domain (CH-C1)

**Contract.** `K` is the first contract in `minimum_cardinality_contracts_found` of
`out/checkers/ch_c1_check.json` at the `sarc-authority-derivation` pin:
`{approval_token, data_residency_region, delegated_role, destination_endpoint_class,
evidence_retention_class, network_zone, operation, resource_environment, workflow_stage}`.

**Sensed-field rule (registered).** A contract field counts as plausibly held in text if its
`costs_v8` source tier is a document-backed remote service: `remote-governance-lookup`
(change and approval records) or `remote-iam-cmdb-lookup` (ownership, residency and
retention records). Machine-generated sources (`remote-deployment-control-lookup`,
`remote-security-telemetry-lookup`) and local tiers do not count. Among the qualifying fields
of `K`, the two with the highest `costs_v8` observation cost are sensed, with ties broken by
property name in ascending order. At the pin this gives
`F_s = {approval_token, data_residency_region}`: costs 2.225 and 1.740, where
`data_residency_region` wins the tie with `evidence_retention_class` by name. All other
fields of `K` are recorded at their true values.

**Items.** The population is `executable_reachable_tuples_v8()` at the pin, in returned order
(27,000 tuples; the run aborts on any other size). Items are
`sorted(random.Random(20261101).sample(range(27000), 1000))`. The validation split is
`set(random.Random(20261102).sample(items, 300))` (30%); the other 700 items (70%) are the
test split. Design facts (true value counts per split, true allow counts) are deterministic
functions of the pin and the seeds; Phase B code computes them and records them in the
manifest before any model call.

**Evidence document.** The jev-v2 §5 generator design is carried over: one synthetic record
per item, phrasing drawn from `random.Random(f"p6-v1:E1:20261103:{i}")`, noise nested across
levels, never hand-edited or committed as data, and every rendered record hashed into the
cache. To stop a sensor inferring a sensed field from a recorded one through the domain's
derivation rules, the document carries no property value except the sensed statements:

```
Change request {ref}
Submitted: {date}
Notes: {filler}
{approval statement}
{residency statement}
```

`{ref}`, `{date}` and `{filler}` are as in jev-v2 §5 (the filler bank mentions neither
approval nor location). Statement banks, verbatim; `{approver}`, `{date}` and `{doc}` are
drawn per item:

| field | value | bank |
|---|---|---|
| `approval_token` | `valid` | `Approval: granted by {approver} on {date}.` / `Change approved by {approver} under {ref}.` / `CAB approval recorded for {ref} on {date}.` |
| `approval_token` | `absent` | `Approval: none recorded.` / `Awaiting approval; no approver has signed off.` / `No CAB approval is on record for this change.` |
| `approval_token` | `expired` | `Approval: granted by {approver} on {date}; the approval has since expired.` / `Change approved by {approver} under {ref}, but the approval lapsed before execution.` / `CAB approval for {ref} expired on {date}.` |
| `data_residency_region` | `us` | `Data residency: United States.` / `Customer data for this resource is stored in US data centres.` / `Residency agreement {doc} places the data in the United States.` |
| `data_residency_region` | `eu` | `Data residency: European Union.` / `Customer data for this resource is stored in EU data centres.` / `Residency agreement {doc} places the data in the European Union.` |
| `data_residency_region` | `apac` | `Data residency: Asia-Pacific.` / `Customer data for this resource is stored in APAC data centres.` / `Residency agreement {doc} places the data in the Asia-Pacific region.` |

**Noise.** As jev-v2 §5, independently per sensed field in the order `approval_token`, then
`data_residency_region`: per item and field, `u ~ Uniform(0, 1)` and a type from `missing`
and `contradictory` with equal probability. At noise level `ν ∈ {0, 0.10, 0.30}` the field's
statement is perturbed iff `u < ν`. `missing` removes the statement line. `contradictory`
keeps it and appends `Comment from {actor}: {opposite}`, where `{opposite}` is drawn from the
bank of a different value of the same field, chosen uniformly. The ground truth is always the
item's true value.

**Calls.** 3,000 records (1,000 items × 3 noise levels) × 2 fields × 2 sensors = 12,000 calls.

**Metrics per cell** (sensor × noise level, test split): verdict-change rate and unsafe rate
with Clopper-Pearson 95% intervals; per field `e_i`, `u_i`, `e_i^+` on the test split; the
**registered bound** `B = Σ (e_i + u_i)` and `B^+ = Σ e_i^+`, with each rate estimated on the
**validation** split at the same sensor and noise level, so that the bound is fixed before the
test data are seen. Whether S3's condition held on the test split is reported per cell.

### 5.5 E2: sensing-aware reduct selection (CH-B1)

**Domain and items.** CH-B1 (`domain_v4`, `losses_v4`); the items, split and seeds of jev-v2
§3 (1,000 items, 300 validation / 700 test). The two seven-attribute reducts of jev-v2 §2:
`R_branch = {approval_token, branch, data_classification, delegated_role, operation,
repository, resource_owner}` and `R_env`, the same with `environment` in place of `branch`.

**Arms.** `approval_token` is sensed in every E2 contract.

- Arm 1: `environment` recorded, `branch` sensed. `R_env` has `F_s = {approval_token}`;
  `R_branch` has `F_s = {approval_token, branch}`.
- Arm 2: `branch` recorded, `environment` sensed. `R_branch` has `F_s = {approval_token}`;
  `R_env` has `F_s = {approval_token, environment}`.

**Selection rule (registered).** Pick the reduct with the smaller `|F_s|`. Ties (none at this
design) go to the smaller validation-estimated `Σ (e_i + u_i)`, then to the name in ascending
order. Under this rule arm 1 picks `R_env` and arm 2 picks `R_branch`. Paper 5's default
choice for CH-B1 is reported alongside, to show whether sensing awareness changes the
selected reduct (claim C7).

**Evidence document.** As E1, one per item and arm, with seed string
`f"p6-v1:E2:{arm}:20261106:{i}"`, carrying only the approval statement (CH-B1 banks: `valid`
and `absent` as in jev-v2) and the arm's second sensed statement:

| field | value | bank (`{slug}` drawn per item) |
|---|---|---|
| `branch` | `main` | `Target branch: main.` / `The change merges into the main branch.` / `Branch under change: main (trunk).` |
| `branch` | `staging` | `Target branch: staging.` / `The change merges into the staging branch.` / `Branch under change: staging.` |
| `branch` | `feature` | `Target branch: a feature branch.` / `The change lands on a feature branch.` / `Branch under change: feature/{slug}.` |
| `environment` | `production` | `Target environment: production.` / `This change deploys to the production environment.` / `Environment: prod (customer-facing).` |
| `environment` | `staging` | `Target environment: staging.` / `This change deploys to the staging environment.` / `Environment: pre-production staging.` |
| `environment` | `development` | `Target environment: development.` / `This change deploys to the development environment.` / `Environment: dev sandbox.` |

Noise as E1, per field in the order `approval_token`, then the arm's second field. Both
reducts of an arm are evaluated on the same readings of the same documents, so each test item
gives a paired pair of verdict-change indicators.

**Calls.** 2 arms × 3,000 records × 2 fields × 2 sensors = 24,000 calls.

**Metric.** Verdict-change rate per reduct, per arm, sensor and noise level (test split);
the exposure difference, picked minus other.

### 5.6 E3: admission ablation (no new calls)

From the E1 caches: `ε ∈ {1%, 5%}`, with thresholds for `ε = 5%` fitted on the same validation
records; and `unknown → deny` against `unknown → escalate`, where an escalated item is counted
as neither allow nor deny. Reported per cell: coverage (the share of test items decided allow
or deny) against exposure (verdict-change rate among decided items) and the unsafe rate.
Expectation, descriptive only: coverage rises with `ε`, and the unsafe rate rises or stays;
no expectation on magnitude.

### 5.7 E4: bound attainment (synthetic, no model)

The N6 configuration: two binary sensed fields `f1`, `f2` with `g = allow` iff both are
`true`. 10,000 synthetic items from `random.Random(20261105)`, each with true values
`(false, true)` or `(true, false)` with equal probability, so every true verdict is deny. The
synthetic sensor reads the item's `false` field as `true` with probability 0.05 and reads
every other field correctly, with no `unknown`. Then `e_1^+ = e_2^+ = 0.025` and
`B^+ = 0.05`, and the allow-ward errors are disjoint by construction. The measured deny-to-allow
rate is compared with `B^+`.

### 5.8 E5: calibration (secondary)

Spiegelhalter Z and Brier skill score per sensor and domain (E1 on CH-C1, E2 on CH-B1), on the
test-split raw scores of every `(field, value)` question, computed as in jev-v1. Expectation,
descriptive: calibration is refuted for both sensors.

## 6. Hypotheses

H1 to H3 form one Holm family at `α = 0.05`. Everything else is descriptive.

- **H1 (E1): no cell violates the registered bound.** For each of the 6 cells (2 sensors × 3
  noise levels) and each of the two inequalities (verdict-change rate against `B`, unsafe rate
  against `B^+`), an exact one-sided binomial test of `H0: rate ≤ bound` on the 700 test items
  gives a p-value. H1's p-value is `min(1, 12 × min p)` (Bonferroni over the 12 tests).
  **Refuted: bound violated** if the Holm-adjusted p < 0.05; otherwise **not refuted: no
  violation detected**, which is never presented as proof that the bound holds in general.
- **H2 (E2): the sensing-minimal reduct has lower exposure.** Paired verdict-change
  indicators (picked reduct, other reduct) at noise 0.30, pooled over both arms and both
  sensors (2,800 pairs). Exact McNemar test, two-sided; CI for the rate difference from a
  paired item bootstrap. **Supported** if the Holm-adjusted p < 0.05 and the picked reduct's
  rate is lower; **refuted** if the Holm-adjusted p < 0.05 and it is higher; otherwise **not
  refuted: no significant difference**.
- **H3 (E4): the N6 configuration attains the bound.** Two one-sided exact binomial tests
  (TOST) of equivalence between the measured deny-to-allow rate and `B^+ = 0.05` with margin
  `δ = 0.01`; H3's p-value is the larger of the two. **Supported: attained** if the
  Holm-adjusted p < 0.05; otherwise **not supported**.

Every bootstrap uses 10,000 resamples from a fresh `random.Random(20261104)`.

## 7. Run order, arm health, cap, cache and slots

- **Order.** E1, then E2, then E3, then E4, then E5. Within E1 and E2: all validation records,
  then the arm health check, then thresholds written and committed, then all test records.
  Within a record: sensors in the order Jev, then Haiku; fields in the order given above.
  Items ascending; noise levels 0, then 0.10, then 0.30.
- **Arm health rule (hard stop), per sensor and experiment, as jev-v3 §3c.** The first 20
  validation records are a smoke check: more than 2 invalid stops the run with `ARM_INVALID`
  before any further call. After the validation split, more than 5% invalid stops it with
  `ARM_INVALID` before any threshold is written or any test-split call is made. Both stops are
  final, logged in the manifest, and a later invocation makes no call.
- **Spending cap: USD 60.00 in total across E1 to E5**, retries and re-requests included,
  enforced before every call with the jev-v2 §10 worst-case bound (UTF-8 request bytes as input
  tokens plus `max_tokens` output tokens for Haiku). A cap stop is `CAP_TRUNCATED` with the
  jev-v2 §10 consequences. Prices as jev-v2 §8 and jev-v3.
- **Retries** as jev-v2 §10.
- **Cache and slots** as jev-v2 §11: append-only raw caches under `responses/` (committed, one
  per experiment, with manifests), every raw response appended before parsing, no credential,
  header or environment value ever written; analysis reads only the caches, the frozen
  threshold files and the pinned siblings; every number in the results and the paper is a
  named slot filled by a single command. The Anthropic and TypeSafe keys live only in `.env`,
  never in prompts, files or messages.

## 10. Choices made in drafting (for the author to confirm before tagging)

The brief leaves these points open; this draft fixes them as follows.

1. **Multi-valued fields** are sensed one-vs-rest, and a field is admitted only when exactly
   one value maps to `true` (§5.1, §5.2).
2. **The sensed-field rule** for CH-C1 is operationalised through the `costs_v8` source tiers
   and costs (§5.4). It selects `approval_token` and `data_residency_region`.
3. **Evidence documents carry no property value but the sensed statements**, so a sensor
   cannot infer a sensed field from a recorded one (CH-B1 pairs `branch` and `environment` one
   to one). jev-v2 rendered recorded fields; this is a design change.
4. **E2 senses `approval_token` in every contract**, so the two reducts in each arm differ in
   `|F_s|` (1 against 2). Without it, one reduct would have no sensed field.
5. **H1 uses a bound estimated on the validation split.** An empirical bound computed on the
   test split itself holds by construction and could not be refuted. H1 is one-sided, and H3 is
   an equivalence test; the brief says "two-sided" for the family, which fits H2 only.
6. **H2 pools both arms and both sensors at noise 0.30**; the other breakdowns are descriptive.
7. **New seeds:** 20261101 (E1 items), 20261102 (E1 split), 20261103 (E1 corpus), 20261104
   (bootstrap), 20261105 (E4), 20261106 (E2 corpus). E2 reuses jev-v2's items and split.
