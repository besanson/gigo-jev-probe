## 1. Setting and invariants

Inherited from paper 5: candidate attributes `A`, reachable tuples `R`, verdict function
`g: R → {allow, deny}`, and a sufficient contract `C ⊆ A` such that `g` is determined by `C` on
`R`.

New objects:

- A partition `C = F_r ∪ F_s`. Recorded fields `F_r` are read from systems of record with
  metadata. Sensed fields `F_s` are produced by sensors.
- A sensor `S_i` for field `i` maps an evidence document `d` to a score `s ∈ [0, 1]` for each
  candidate value of field `i` (§5.1).
- An admission policy `A_i` maps scores to `true`, `false` or `unknown` using thresholds
  frozen on validation split A at false-positive target `ε` (§5.2). `unknown` routes to deny.
- A **sensed record** `[F13]`: `(request_id, resource_id, field, value, score, admission,
  admission_policy_version, sensor id and version, source document SHA-256, sensed_at)`. It
  carries metadata, so SARC-DQ predicates apply to it (freshness of sensing, sensor version
  pin, admission policy version pin, lineage to the document and to the request and
  resource it was sensed for). The sensor never emits a verdict.
- **Contract evaluation from observations.** Given an observed value for every field of `C`
  (recorded values as recorded, sensed values as admitted, derived values computed as in I2),
  the verdict is `g(t')` for any `t' ∈ R` that agrees with the observations on `C`. Sufficiency
  makes this well defined. If any sensed field is `unknown`, or no reachable tuple agrees with
  the observations, the verdict is `deny`.
- **Exposure**: the event `g(recorded ∪ sensed) ≠ g(recorded ∪ true)`. A change from deny to
  allow is *unsafe*; a change from allow to deny is *fail-closed*.

Per sensed field `i` and a distribution over items `[F1]`: `e_i` is the probability that field
`i` is admitted with a wrong value (a definite value different from the true value); `u_i` is
the probability that field `i` is `unknown`. There is no directional term.

**Invariants.**

- **I1.** The sensor writes an observation; the deterministic contract computes the verdict.
  The admission policy is a threshold with abstention per field, never a weighted combination
  across fields.
- **I2 `[F7]`.** A sensor is asked only what the document asserts: whether an approval is
  recorded or not recorded, the date it gives, whether an approver is named, where it says the
  data are stored, and which branch or environment it names. Validity, scope and expiry are
  never sensed. They are computed deterministically from recorded fields plus the admitted
  sensed assertion (§5.4).

## 2. Architecture registered (claim C1)

A sensed field enters the gate only as a sensed record (§1) with provenance, score and
admission stamp. The gate of paper 1 and the compiler of paper 5 are unchanged; this paper
adds a record type and a cost model. Sensed records live in the governed buffer and are never
written to source systems.

`[F13]` Stamp enforcement (a record whose `request_id`, `resource_id`, sensor version or
`admission_policy_version` does not match the request being decided is rejected, and the field
is `unknown`) is covered by unit tests in Phase B. It is stated as not experimentally
evaluated: E1 to E5 never present a mismatched record.

## 3. Propositions (statements registered; proofs and checkers in Phase B)

- **S1 (union bound) `[F1]` `[F5]`.** For a contract with sensed-field set `F_s`,
  `P(verdict change) ≤ Σ_{i∈F_s} (e_i + u_i)` and `P(deny→allow) ≤ Σ_{i∈F_s} e_i`.
  A verdict change requires at least one sensed field whose admitted value is wrong or
  unknown; a deny-to-allow change requires at least one wrongly admitted field, because
  `unknown` denies. S1 is labelled an **instantiation** of union-bound reasoning over program
  events (Barthe et al., ICALP 2016), not a new inequality.
- **S2 (monotonicity for nested sets) `[F6]`.** For two sufficient contracts whose sensed-field
  sets are nested, `F_s' ⊆ F_s`, read by the same sensors on the same documents, the S1 bound of
  `F_s'` does not exceed that of `F_s`. No claim is made for non-nested sets. The selection
  objective is the **estimated bound** `Σ_{i∈F_s} (ê_i + û_i)` (§5.2), which is a valid cost
  model under paper 5's `observation_costs` interface. No new solver is needed.
- **S3 (fail-closed) `[F1]`.** Call a sensing configuration *deny-ward* if, for every reachable
  tuple `t ∈ R` with `g(t) = deny` and every observation vector that agrees with `t` on `F_r`
  and whose sensed fields are each either true or admitted with any wrong value, jointly, the
  contract evaluates to `deny`. Deny-ward is defined globally over `R` and over joint errors,
  not field by field. If `unknown` routes to deny and the configuration is deny-ward, then
  `P(deny→allow) = 0`. E1 and E2 report whether the condition held.
- **N6 (negative) `[F1]`.** Two witnesses:
  (a) a two-field configuration with disjoint wrong admissions in which the S1 deny-to-allow
  bound is attained; and
  (b) a **joint-error witness**: an AND contract (`allow` iff both fields are `true`), true
  values `(false, false)`, and a sensor that admits both fields wrongly together with
  probability `q` and never one alone. Every single-field error is harmless, so a
  field-by-field direction test would call the configuration deny-ward, yet
  `P(deny→allow) = q`. This is why S3's condition is global.

Checkers (Phase B): exhaustive over small synthetic sensors with declared error rates;
property-based tests that the inequalities hold in every generated case; witness generators
for N6 (a) and (b). Each statement is tagged `machine-checked` only where a checker covers it,
`checked-scope-only` otherwise, and `pending-human-review` for the general proofs.

### 5.2 Validation splits A and B, admission and bound estimation `[F2]` `[F8]`

Each experiment's validation split (30% of items) is divided once, before any call:
`split A = set(random.Random(20261107).sample(sorted(validation), len(validation) // 2))`, and
split B is the rest. The test split is the remaining 70% of items, as in v1.

- **Admission (split A).** For each sensor, experiment, field and candidate value `v`,
  thresholds are fitted on split A, pooled over the three noise levels, by the jev-v2 §7
  procedure **against the assertion label** (§5.4, what the document shows), with
  false-positive target `ε`: `τ_v^true` is the smallest candidate with at most `ε` of split-A
  records whose assertion label for `v` is `0` scoring at least `τ_v^true`; `τ_v^false` is the
  largest candidate with at most `ε` of split-A records whose assertion label for `v` is `1`
  scoring at most `τ_v^false`. The threshold measures reading fidelity. `ε = 1%` (E3 adds `ε = 5%`). `ε` is a
  fitting target on split A, not a guarantee; the quantities that carry the guarantee are the
  split-B upper bounds below. Invalid answers are excluded from threshold setting.
- **Mapping.** Each value's score maps to `true`, `false` or `unknown` as in jev-v2 §7. The
  field's admitted value is `v` if exactly one value maps to `true`; otherwise the field is
  `unknown`, which denies.
- **Estimation (split B).** With the frozen thresholds, for each sensor, field and noise level
  separately, `ê_i` and `û_i` are the one-sided 95% Clopper-Pearson **upper** bounds on the
  split-B rates of wrong admission and of `unknown`, **against the truth label**. Exposure
  must count a faithfully read but false document as a wrong admission, so a correct reading
  of a contradictory record can still be an admitted-wrong event here. The registered bounds per cell are
  `B^+ = Σ_{i∈F_s} ê_i` (deny to allow) and `B = Σ_{i∈F_s} (ê_i + û_i)` (any change).
- Thresholds and the split-B estimates are written to a committed file before any test-split
  call of that experiment.

### 5.4 E1: the bound on a second domain (CH-C1)

**Contract.** `K` is the first contract in `minimum_cardinality_contracts_found` of
`out/checkers/ch_c1_check.json` at the `sarc-authority-derivation` pin:
`{approval_token, data_residency_region, delegated_role, destination_endpoint_class,
evidence_retention_class, network_zone, operation, resource_environment, workflow_stage}`.

**Sensed-field rule (registered, as v1).** A contract field counts as plausibly held in text if
its `costs_v8` source tier is a document-backed remote service: `remote-governance-lookup` or
`remote-iam-cmdb-lookup`. Among the qualifying fields of `K`, the two with the highest
`costs_v8` observation cost are sensed, ties broken by property name ascending. At the pin
this selects `approval_token` (2.225) and `data_residency_region` (1.740). All other fields
of `K` are recorded at their true values.

**Sensed assertions and derivation `[F7]`.** Under I2, `approval_token` is not sensed
directly. The sensed field is `approval_assertion ∈ {not_recorded} ∪ {recorded:<d> : d ∈ D}`,
with the registered date set
`D = {2026-06-01, 2026-06-15, 2026-07-01, 2026-07-15, 2026-08-01, 2026-08-15}`. Each item also
has a recorded `request_date` (a recorded field of the request, never rendered into the
document). `approval_token` is then computed deterministically: `absent` if the admitted
assertion is `not_recorded`; `valid` if it is `recorded:<d>` and
`0 ≤ request_date − d ≤ 30` days; `expired` if it is `recorded:<d>` otherwise. The generator
draws, from the item's generator: for a true `valid` item, `d` uniform on `D` and
`request_date = d + k` with `k` uniform on `{0, …, 30}`; for a true `expired` item, `d` uniform
on `D` and `k` uniform on `{31, …, 90}`; for a true `absent` item, `request_date` uniform on
`2026-06-01 + {0, …, 120}` days. `data_residency_region` is sensed as the assertion itself
(the stated region). F_s for the bound is `{approval_assertion, data_residency_region}`.

**Items.** The population is `executable_reachable_tuples_v8()` at the pin, in returned order
(27,000 tuples; the run aborts on any other size). Items are
`sorted(random.Random(20261101).sample(range(27000), 1000))`. The validation split is
`set(random.Random(20261102).sample(items, 300))` (30%), divided into A and B as §5.2; the
other 700 items (70%) are the test split. Design facts are deterministic functions of the pin
and the seeds; Phase B code computes them and records them in the manifest before any model
call.

**Evidence document.** The jev-v2 §5 generator design is carried over: one synthetic record
per item, phrasing drawn from `random.Random(f"p6-v1.1:E1:20261103:{i}")`, noise nested across
levels, never hand-edited or committed as data, and every rendered record hashed into the
cache. The document carries no property value except the sensed statements:

```
Change request {ref}
Submitted: {submitted}
Notes: {filler}
{approval statement}
{residency statement}
```

`{ref}` and `{filler}` are as in jev-v2 §5 (the filler bank mentions neither approval nor
location). `{submitted}` is a date drawn per item from `2026-05-01 + {0, …, 30}` days and is
independent of `request_date`. `[F7]` The approval statement asserts only whether an approval
is recorded, its date and the approver's name; it never says valid, current, expired or
lapsed.

**Statement banks `[F12]`.** Each value has a validation bank, used for every record of a
validation item (splits A and B), and a disjoint test bank, used for every record of a test
item. No test phrase occurs in any validation bank. `{approver}`, `{doc}` and `{ref}` are drawn
per item; `{d}` is the item's approval date.

| field | value | validation bank (verbatim) | test bank (verbatim) |
|---|---|---|---|
| `approval_assertion` | `recorded:<d>` | `Approval: granted by {approver} on {d}.` / `Change approved by {approver} on {d}.` / `CAB approval recorded for {ref} on {d}.` | `Signed off by {approver}, dated {d}.` / `{approver} recorded an approval for this change on {d}.` / `Approval entry dated {d}, approver {approver}.` |
| `approval_assertion` | `not_recorded` | `Approval: none recorded.` / `Awaiting approval; no approver has signed off.` / `No CAB approval is on record for this change.` | `No sign-off has been entered for this change.` / `The approval log for this change is empty.` / `Nobody has approved this change yet.` |
| `data_residency_region` | `us` | `Data residency: United States.` / `Customer data for this resource is stored in US data centres.` / `Residency agreement {doc} places the data in the United States.` | `Hosting region: US.` / `The data for this resource are kept in the United States.` / `Storage location per contract {doc}: United States.` |
| `data_residency_region` | `eu` | `Data residency: European Union.` / `Customer data for this resource is stored in EU data centres.` / `Residency agreement {doc} places the data in the European Union.` | `Hosting region: EU.` / `The data for this resource are kept in the European Union.` / `Storage location per contract {doc}: European Union.` |
| `data_residency_region` | `apac` | `Data residency: Asia-Pacific.` / `Customer data for this resource is stored in APAC data centres.` / `Residency agreement {doc} places the data in the Asia-Pacific region.` | `Hosting region: APAC.` / `The data for this resource are kept in the Asia-Pacific region.` / `Storage location per contract {doc}: Asia-Pacific.` |

**Noise.** As jev-v2 §5, independently per sensed field in the order `approval_assertion`,
then `data_residency_region`: per item and field, `u ~ Uniform(0, 1)` and a type from
`missing` and `contradictory` with equal probability. At noise level `ν ∈ {0, 0.10, 0.30}` the
field's statement is perturbed iff `u < ν`. `missing` removes the statement line.
`contradictory` keeps it and appends `Comment from {actor}: {opposite}`, where `{opposite}` is
drawn from the same split's bank of a different value of the same field, chosen uniformly
(for `approval_assertion`, a different value may be `not_recorded` or another date).

**Labels `[F11]`.** Each item and field carries two labels. The **truth label** is the item's
true value (for `approval_assertion`, the value the generator used). The **assertion label**
for each candidate value `v` is `1` if the rendered record contains a statement from `v`'s
bank (so both values are asserted on a contradictory record, and none on a missing one), and
`0` otherwise. Admission thresholds (§5.2) and calibration (E5) are measured against the
assertion label; split-B estimates and exposure (E1 to E3) against the truth label.

**Calls.** 3,000 records (1,000 items × 3 noise levels) × 2 fields × 2 sensors = 12,000 calls.

**Metrics per cell** (sensor × noise level, test split) `[F10]`: the **unsafe rate**
(deny-to-allow changes over **all** test items) and the verdict-change rate, both with
Clopper-Pearson 95% intervals; per field the test-split rates of wrong admission and
`unknown`; the registered bounds `B^+` and `B` from split B (§5.2). Whether S3's global
condition held on the test split is reported per cell.

### 5.6 E3: admission ablation (no new calls)

From the E1 caches: `ε ∈ {1%, 5%}`, with thresholds for `ε = 5%` fitted on the same split A;
and `unknown → deny` against `unknown → escalate`, where an escalated item is counted as
neither allow nor deny. `[F10]` Registered definitions: **coverage** is the fraction of test
items decided allow or deny; the **unsafe rate** is deny-to-allow changes over **all** test
items, escalated items included in the denominator; exposure among decided items is reported
alongside. Expectation, descriptive only: coverage rises with `ε`, and the unsafe rate rises
or stays; no expectation on magnitude.

### 5.7 E4: witness and implementation check (synthetic, no model) `[F9]`

E4 is not a hypothesis test. It checks that the Phase C pipeline reproduces the two N6
witnesses exactly as the Phase B checkers compute them.

- (a) Two binary sensed fields `f1`, `f2`, `g = allow` iff both are `true`; 10,000 synthetic
  items from `random.Random(20261105)` with true values `(false, true)` or `(true, false)` with
  equal probability; the sensor reads the item's `false` field as `true` with probability 0.05
  and every other field correctly, with no `unknown`. Then `e_1 = e_2 = 0.025`, the S1
  deny-to-allow bound is 0.05, and it is attained in expectation.
- (b) The joint-error witness of N6 (b) with `q = 0.05`, 10,000 items from
  `random.Random(20261108)`: true values `(false, false)`; with probability `q` both fields are
  admitted as `true`, otherwise both are correct.

Reported: measured deny-to-allow rate with a Clopper-Pearson 95% interval, the S1 bound, and
the checker's exact value, per witness. The check passes if the pipeline's per-item outcomes
equal the checker's.

### 5.8 E5: calibration (secondary) `[F11]`

Spiegelhalter Z and Brier skill score per sensor and domain (E1 on CH-C1, E2 on CH-B1), on the
test-split raw scores of every `(field, value)` question, computed as in jev-v1, **against the
assertion label**. Expectation, descriptive: calibration is refuted for both sensors.

## 6. Hypotheses `[F9]`

The Holm family is H1 and H2, at `α = 0.05`. H3 of v1 is withdrawn (E4 is a witness and
implementation check). Everything else is descriptive.

- **H1 (E1) `[F2]`: no cell's unsafe rate exceeds its registered bound.** For each of the 6
  cells (2 sensors × 3 noise levels), an exact one-sided binomial test of
  `H0: unsafe rate ≤ B^+` on the 700 test items, where `B^+` is the split-B Clopper-Pearson
  bound of §5.2 for that cell. H1's p-value is `min(1, 6 × min p)` (Bonferroni over the 6
  cells). **Refuted: bound violated** if the Holm-adjusted p < 0.05; otherwise **not refuted:
  no violation detected**, which is never presented as proof that the bound holds in general.
  The verdict-change rate against `B` is reported per cell, descriptive.
- **H2 (E2) `[F3]`: the picked reduct has lower exposure**, tested **separately per sensor and
  per arm** (four tests: Jev arm 1, Jev arm 2, Haiku arm 1, Haiku arm 2), each on the paired
  verdict-change indicators (picked reduct, other reduct) of the 700 test items at noise
  0.30. Exact McNemar test, two-sided. **Supported** if the Holm-adjusted p < 0.05 and the
  picked reduct's rate is lower; **refuted** if the Holm-adjusted p < 0.05 and it is higher;
  otherwise **not refuted: no significant difference**. There is no pooled H2.

Holm is applied over the five p-values (H1 and the four H2 tests).

**Bootstrap `[F3]`.** Every confidence interval from resampling is an **item-clustered**
bootstrap: items are resampled with replacement, keeping all observations of an item (every
noise level, field, sensor and reduct) together. 10,000 resamples from a fresh
`random.Random(20261104)`.

## 7. Run order, arm health, cap, cache and slots

- **Order.** E1, then E2, then E3, then E4, then E5. Within E1 and E2: all validation records
  (splits A and B), then the arm health check, then thresholds fitted on A and bounds estimated
  on B, written and committed, then all test records. Within a record: sensors in the order
  Jev, then Haiku; fields in the order given above. Items ascending; noise levels 0, then 0.10,
  then 0.30.
- **Arm health rule (hard stop), per sensor and experiment, as jev-v3 §3c.** The first 20
  validation records are a smoke check: more than 2 invalid stops the run with `ARM_INVALID`
  before any further call. After the validation split, more than 5% invalid stops it with
  `ARM_INVALID` before any threshold is written or any test-split call is made. Both stops are
  final, logged in the manifest, and a later invocation makes no call.
- **Spending cap: USD 60.00 in total across E1 to E5**, retries and re-requests included,
  enforced before every call with the jev-v2 §10 worst-case bound (UTF-8 request bytes as input
  tokens plus `max_tokens` output tokens for Haiku). A cap stop is `CAP_TRUNCATED` with the
  jev-v2 §10 consequences. Prices as jev-v2 §8 and jev-v3.
- **Retries** as jev-v2 §10.
- **Cache and slots** as jev-v2 §11: append-only raw caches under `responses/` (committed, one
  per experiment, with manifests), every raw response appended before parsing, no credential,
  header or environment value ever written; analysis reads only the caches, the frozen
  threshold files and the pinned siblings; every number in the results and the paper is a
  named slot filled by a single command. The Anthropic and TypeSafe keys live only in `.env`,
  never in prompts, files or messages.

## 10. Limitations `[F12]`

The validation and test phrase banks are disjoint, but the rest of the document is shared
across splits: the header lines, the filler bank, the noise templates, the date set `D`, the
names drawn for `{approver}` and `{actor}`, and the record layout. A sensor can therefore still
benefit from surface regularities that carry over from validation to test. All documents are
synthetic, one statement per sensed field, in English. Stamp enforcement (`[F13]`) is tested
by unit tests only. The corpora are constructed; no prevalence claim is made.
